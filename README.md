# 我的理財手帳｜粉紅小豬儲蓄儀表板

在原專案上調整的繁體中文個人理財網站：白色背景、淺灰卡片、深色大字，以大型粉紅 SVG 小豬與儲蓄圓環為主視覺。沒有財務健檢、健康分數、投資分析或複雜圖表。

使用 React、TypeScript、Vite、Tailwind CSS、Zod 與 Lucide。粉紅小豬是專案內 SVG 插圖，不是 Emoji，不需要外部圖片服務。

## 已提供的功能

- 首頁：總資產、本月收入、本月支出、本月結餘、儲蓄目標、30歲年收入目標、最近收支紀錄。
- 存錢明細：新增、編輯、刪除、月份篩選、起訖日期查詢、日期升降序、來源／存入帳戶、各筆存款後累積金額與月份／全部存款總額。
- 帳戶總覽：新增、修改、刪除資產與負債／信用卡帳戶；可對帳設定目前餘額。
- 收支紀錄：收入、支出、帳戶間轉帳，支援 CRUD、月份篩選、起訖日期查詢、日期排序。
- 收支類別：收入與支出各自管理，可新增、修改、刪除未使用的類別。
- 儲蓄目標：連結指定資產帳戶，可新增、修改、封存、還原與刪除；完成日期及金額永久留作紀錄，直到目標被刪除。
- 30歲目標：目標年齡、目標年收入、可選截止日期；按年度實際收入自動計算達成度，與資產及存款獨立。

全新使用者的所有帳戶餘額、收入、支出均為 **零**，不建立任何虛構交易。新帳簿預設「年底郵局儲蓄」，指定郵局，目標 NT$40,000、日期 2026/12/31；30歲目標為年收入 NT$1,000,000。這些是可編輯的目標，不代表已經擁有的存款或收入。

## 第一次使用

1. 到「帳戶總覽」用「編輯帳戶」填入既有餘額；這是期初設定／對帳，**不當作收入**。
2. 有新薪資、支出時，到「收支紀錄」記一筆，選日期、帳戶及類別。
3. 要把銀行或現金轉到郵局存錢，按「新增存款」，確認所屬目標、存入帳戶，輸入日期、金額、資金來源與備註。
4. 「資金來源」選自己的銀行或現金代表 **轉帳**，不增加總資產，也不計收入；如果確實是尚未記錄的新收入，可明確選「外部新收入」，並選擇收入類別。
5. 既有收入已入帳後，請勿又選外部收入重複登記；應用轉帳將它移到郵局。
6. 一般收入或轉帳存入某帳戶，若該帳戶只有一個儲蓄目標，也會自動關聯存錢明細。同帳戶有多個目標時，請使用「新增存款」明確選擇目標。
7. 存款將同時出現在「存錢明細」及「收支紀錄」，兩處操作的是同一筆資料，**不會各建立一筆交易**。
8. 編輯或刪除紀錄後，帳戶、累積存款、總資產與進度會重新計算；如果造成餘額不足或超額還信用卡，會拒絕操作，保留原資料。

### 小豬與動畫

新增存款後，一枚金幣從上方落入小豬、小豬輕跳，進度環與黑色百分比平滑變化。達到 80% 提示「快達標了！」；首次達到 100% 顯示「恭喜！儲蓄目標達成！」、開心動畫與適量彩帶。

重新整理不會重播存款或首次慶祝；可以從「完成紀錄」手動重看。啟用系統「減少動態效果」後，動畫停止，金額與百分比直接更新。進度取指定帳戶**實際餘額**，不是存款明細金額的簡單加總。

多個目標連結同一帳戶時都讀取同一餘額，不代表資金已分開配置，也不會重複加到總資產。已完成後餘額下降，圓環反映目前餘額，原完成日期及金額仍保留。

## 金額的定義

| 指標／操作       | 計算或影響                                                                 |
| ---------------- | -------------------------------------------------------------------------- |
| 總資產           | 所有資產帳戶的實際餘額合計；不將儲蓄目標或人生目標再加一次                 |
| 本月收入／支出   | 當月日期的實際收入／支出紀錄加總，不含轉帳與對帳                           |
| 本月結餘         | 本月收入減本月支出，可為負數                                               |
| 淨資產           | 總資產減總負債，可在帳戶總覽查看                                           |
| 銀行轉郵局       | 來源扣款、目的增加，總資產與收入不變                                       |
| 信用卡刷卡       | 支出計一次，同時增加負債                                                   |
| 繳信用卡費       | 從資產帳戶轉到信用卡，降低資產與負債，不重複列支                           |
| 儲蓄進度         | 指定帳戶餘額 ÷ 目標，最高顯示 100%，尚差最低為零                           |
| 當月存款總額     | 該月份明確關聯儲蓄目標的存入紀錄加總                                       |
| 累積存款紀錄總額 | 所有存款明細金額加總，不是目前可用餘額                                     |
| 存款後累積金額   | 依日期及同日登記順序，使用帳戶對帳基數與所有收支重算該筆後餘額；支出會扣除 |
| 目前年收入       | 所選年度的實際收入紀錄加總，轉帳、資產總額與期初餘額不混入                 |

所有金額以新臺幣整數記錄。日期不可晚於今天；期初餘額對帳與回填日期的紀錄會影響重新計算的歷史累積數字，並非銀行提供的原始歷史餘額證明。

### 30歲人生目標

卡片預設「30歲前達成年收入 NT$1,000,000」，可自由修改目標年齡、金額與截止日。首頁下方顯示主要人生目標；在「儲蓄目標」頁面的「長期人生目標」區塊可新增、修改其他人生目標，所有卡片使用所選年度的實際收入，與存款及資產分開計算。年度選擇器決定加總哪一年的收入，新增收入的日期決定它屬於哪一年。

「紀錄一筆收入」使用實際收支表單，不是直接填一個無紀錄的年收入數字。更改年收入目標不會改動郵局目標、帳戶或存款。

### 查詢、封存與導覽

- 導覽固定為「首頁、收支紀錄、存錢明細、儲蓄目標、帳戶總覽」。
- 存錢明細有來源帳戶；外部收入明確標為「外部收入」，與帳戶轉帳區分。
- 月份與日期區間可合併查詢，包含起始／結束當天。「清除篩選」可回到全部資料，查詢不會修改紀錄。
- 存款月份總額仍計算整個所選月份；日期查詢合計另外顯示，避免把局部日期當作整月金額。
- 在「儲蓄目標」點「封存目標」，會隱藏首頁上的該目標並停止新增存款入口，但不刪交易、帳戶、餘額或完成紀錄。可用「查看已封存目標」還原，原本存款仍可編輯或刪除。
- 封存目標不因帳戶後續變動而自動觸發達標慶祝。還原後會按目前真實餘額重新檢查進度。
- 這次保留原畫面，只整合功能；不加入財務健檢、風險分數或投資分析。

## 原始資料保留與轉換

沿用 `my-finance-book.v3`，新增封存狀態及其他人生目標採可選欄位；既有 v3 不需要重置，現有目標名稱與實際紀錄不會被預設值覆蓋。新版使用 `my-finance-book.v3`，原有 `my-finance-dashboard.v1` 與 `my-finance-quests.v2` **不刪除、不覆寫**。

- 先讀 v3；沒有 v3 時才進行一次轉換。原 v1 帳戶與交易保留，v2 更新後的儲蓄金額帶入對應帳戶，其他帳戶不因改版而清空。
- v1 原紀錄已包含在當時帳戶餘額裡，因此標記為已結算，**不再次套用到餘額**；仍保留其收入／支出日期、金額與備註，也可以編輯／刪除，僅套用修改前後的差額。
- v2 只記了累積金額、沒有逐筆日期與來源；新版保留它的帳戶餘額與完成紀錄，**不捏造不存在的歷史存款明細或收入**。
- v2 新建立的獨立目標會對應至獨立資產帳戶；原本有 v1 關聯的目標繼續使用該帳戶。轉換前原文保留在舊 key，供日後必要時修復。
- 資料無效或損毀時停止寫入，不用零值默默取代；請勿清除網站資料。
- 儲存空間不足時整筆操作不套用，不顯示假成功。不同分頁更新造成版本衝突時會阻止覆蓋，請先重新整理。
- 刪除目標只解除紀錄關聯，保留交易與帳戶；帳戶或類別仍有紀錄關聯時不能刪除。

## 登入、儲存與隱私的實際狀態

**現有專案沒有登入驗證、後端、私人資料庫或跨裝置同步。** 本次保留這個架構，沒有加入會讓人誤以為安全的前端密碼鎖。

- 資料使用瀏覽器 localStorage，重新整理、關閉後在相同瀏覽器設定檔及相同網址重開仍會存在；**不會上傳 GitHub Repository 或 GitHub Pages**。
- GitHub Pages 提供公開前端，本身不提供私人資料庫或登入保護。公開程式碼／網站不會自動公開你的瀏覽器資料；前端不能保存祕密金鑰。
- 本機資料**未加密**，可使用該瀏覽器的人或能在同一來源執行的程式可能讀到內容，請使用可信任的個人裝置。
- 清除網站資料、無痕模式結束、更換裝置、瀏覽器或網址，可能無法讀取原資料；目前沒有登入後自動同步、雲端備份或還原保證。
- 若要真正的私人登入與跨裝置持久保存，需要另行設計受保護的後端、驗證及資料庫；不能只靠 Pages 或在前端寫一組帳密。

## Windows 新手安裝與開啟

### 1. 安裝 Node.js

從 [Node.js 官方網站](https://nodejs.org/) 安裝 **Node.js 24 LTS**（包含 npm），完成後重開 PowerShell：

```powershell
node --version
npm.cmd --version
```

應顯示版本號。本版本以 Node 24 驗證，也支援 Node 22.12 以上。

### 2. 取得程式碼

可在 GitHub 按 **Code → Download ZIP**，解壓縮後進入包含 `package.json` 的資料夾。在檔案總管網址列輸入 `powershell`，按 Enter。

也可安裝 [Git for Windows](https://git-scm.com/downloads/win)，再執行：

```powershell
cd "$HOME\Documents"
git clone https://github.com/zhewei1010-NSYSU/Finance-Achievement.git
cd Finance-Achievement
```

### 3. 安裝依賴

```powershell
npm.cmd ci
```

第一次及更新依賴後需要安裝；保留 `package-lock.json`。安裝需要網路，日常使用不連接任何銀行或資料服務。

### 4. 啟動網站

```powershell
npm.cmd run dev -- --port 5173 --strictPort
```

在自己的電腦瀏覽器輸入 `http://127.0.0.1:5173`。終端機要保持開啟，停止時按 `Ctrl+C`。

- 下次使用只要切到專案資料夾再執行啟動命令。
- 請保持相同網址，`localhost` 和 `127.0.0.1` 的本機資料不共用。
- `--strictPort` 避免連接埠被占用時自動換網址；若提示占用，先關閉舊伺服器。
- `npm.cmd` 可避開 PowerShell 對 `npm.ps1` 的限制，不必關閉系統安全政策。
- 若出現 `ENOENT package.json`，請先用 `cd` 進入正確資料夾。
- 更新依賴前先停止開發伺服器。如出現 `Outdated Optimize Dep`，停止後用 `npm.cmd run dev -- --port 5173 --strictPort --force` 重啟。
- 本機伺服器只綁定 loopback，不開放外網或區網；手機版可用桌面開發者工具切換尺寸預覽。

## GitHub Pages

`.github/workflows/pages.yml` 提供手動部署，**推送不會自動發布**。它會使用鎖定依賴、執行測試、以 `/Finance-Achievement/` 路徑建置，僅上傳 `dist/`。官方 Actions 已固定 commit SHA，不需另存部署金鑰。

1. 到儲存庫 **Settings → Pages → Build and deployment → Source** 選 **GitHub Actions**。
2. 到 **Actions → Deploy GitHub Pages → Run workflow**，分支選 `main`，再執行。
3. 等 `build` 與 `deploy` 都成功後，從該次執行的 `github-pages` environment 開啟實際網址。
4. 每次想更新線上版本，重新執行這個流程。停用請用 Settings → Pages 的 Unpublish site。

公開儲存庫可使用免費 Pages；私人儲存庫是否支援以 GitHub 方案為準。[官方說明](https://docs.github.com/en/pages/getting-started-with-github-pages/about-github-pages)

Pages 網站沒有登入保護，前端 JavaScript 也會送到訪客瀏覽器；請勿把密碼、金鑰或真實財務檔案寫入程式碼。網站搬到另一個網址來源時，本機資料不會自動移轉。

同一個 Pages 網址更新新版後，舊版儲蓄目標會在**原瀏覽器**自動帶入，無需清除網站資料；若暫時看到舊版，先重新整理快取，不要清除 localStorage。
